## Fifth review repair completed

### P2 — preserve redoable generated output bytes during startup recovery

`ProjectUnitOfWork` snapshots canonical JSON documents rather than binary media. In the real Generation sequence, undoing `production.register_take` and then `generation.register_output` can leave `artifacts/generated_<attempt>.*` bytes present while both the Take and artifact reference are absent from current canonical documents. Those bytes remain required by the current durable Redo branch.

Repair `dcb5f6158f1a92225501904ddad0fbe6309162e7` derives protected managed paths only from committed `project.json` snapshots in the current `history.entries[history.cursor:]` redo suffix. Historical schema-v1 snapshots are migrated only in memory for validation. Registered current paths and redo-owned paths are preserved; a later canonical commit truncates the redo suffix through the existing UOW contract and automatically removes that protection. Binary media does not become part of UOW snapshots and no new authority is introduced.

Regression `fad2134f02cddb9a6ac3f364d76543c2d068cb8d` proves both boundaries:

- output registration + Take registration -> two Undo -> startup recovery -> two Redo preserves exact generated bytes and restores original artifact/Take identities;
- the same two Undo operations followed by a new canonical commit truncate Redo, after which startup recovery quarantines the now-genuine orphan bytes.

## Sixth Draft repair completed

### P2 — recover prepared-audio hard-crash publications

The current prepared-audio upload and artifact-promotion paths stage under `assets/.aud_<uuid>...upload|promote`, atomically move bytes to final `assets/aud_<uuid>.*`, probe those canonical bytes and only then persist the owning `ProjectReference`. Normal exception handling removes an unregistered staging/final file, but hard process loss can occur before that cleanup and before registration.

Archive already treats both the final `aud_<uuid>` namespace and leading-dot staging names as self-identifying managed publication state and fails closed when they are unregistered. Startup recovery previously scanned no `assets` root and recognized no `aud_` namespace, so restart could not perform the reconciliation that archive instructed the user to trigger.

Regression commit `44d7e036230f50e2a82cd908da13ec67508bd041` extends `tests/test_stage19_art_orphan_recovery.py` with deterministic cases for:

- unregistered final `assets/aud_<uuid>.wav` bytes;
- crash-left `.aud_<uuid>...upload` staging bytes;
- crash-left `.aud_<uuid>...promote` staging bytes;
- archive rejection before recovery and successful archive after recovery;
- exact-byte quarantine outside the canonical project tree;
- preservation of a registered `aud_<uuid>` ProjectReference;
- preservation of ordinary near-miss `assets/aud_preview.wav`.

Repair commit `9b56d5f2fb071e212bf9fcf5900301d8f6ac1d28` adds `assets` to managed startup scanning and synchronizes crash-identifiable filename matching with the archive-owned `aud_<32-hex>` namespace, including an optional leading dot for interrupted staging names. Current registered paths and current redo-owned paths are checked before filename matching, so this repair does not override ProjectReference authority or the fifth repair's Redo ownership. Ordinary unregistered assets remain portable when their names do not match an exact self-identifying UV namespace.
