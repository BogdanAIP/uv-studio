## Fifth review repair in progress

### P2 — preserve redoable generated output bytes during startup recovery

`ProjectUnitOfWork` intentionally snapshots canonical JSON documents, not binary media. Generation publication therefore leaves `artifacts/generated_<attempt>.*` bytes in place when `generation.register_output` is undone so a later Redo can restore the exact `ProjectReference`. In the real Generation sequence, `production.register_take` is committed after output registration, so two Undo operations can leave the generated bytes present while both the Take and artifact reference are absent from current canonical documents.

Prior startup managed-output recovery classified any unregistered self-identifying `generated_attempt_*` file as crash-left orphan media. Reopening a project between those Undo and Redo operations could therefore quarantine bytes still owned by the current durable redo branch; Redo would restore metadata pointing at a missing file.

Material repair `dcb5f6158f1a92225501904ddad0fbe6309162e7` derives protected managed paths only from committed `project.json` snapshots in the current `history.entries[history.cursor:]` redo suffix. Historical schema-v1 snapshots are migrated only for validation. Registered current paths and redo-owned paths are preserved; a new canonical commit truncates the redo suffix through the existing UOW contract and automatically removes that protection. Binary media does not become part of UOW snapshots and no new authority is introduced.

Regression commit `fad2134f02cddb9a6ac3f364d76543c2d068cb8d` adds `tests/test_stage19_redo_output_recovery.py` with two deterministic cases:

- output registration + Take registration -> two Undo -> startup recovery -> two Redo preserves the exact generated bytes and restores the original artifact/Take identities;
- the same two Undo operations followed by a new canonical commit truncate Redo, after which startup recovery again quarantines the now-genuine orphan bytes.

The material repair is awaiting one exact synchronized Draft-head CI after this context update.
